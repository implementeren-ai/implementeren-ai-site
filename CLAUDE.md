# implementeren-ai-site: repo guide for Claude

Astro site for Implementeren.ai (https://implementeren.ai) on Cloudflare Pages. The company was
called ClaudeZakelijk until October 2026; the old domain claudezakelijk.nl 301-redirects to
implementeren.ai. Branch `main` auto-deploys (~60-90s) via the GitHub Actions workflow
`.github/workflows/deploy.yml`, whose deploy job runs in the `production` environment (only
`main` may use it); that is the only production deploy path.
If a merge does not go live, check the Actions run (`gh run list`) before anything else.

## How changes go live

Nobody pushes to `main`. Every change is a branch plus a pull request. Max is the only code owner
(`.github/CODEOWNERS`) and the only authority on this repo: nothing ever needs Camiel's approval.
A PR from someone else (Sweder, Camiel) goes in after 1 approval from Max. Max merges his own PRs
himself, without any review: ruleset `25944613` ("main: reviewed PRs only") has a permanent bypass
for the org admin (only `maxkwaaste`) in `pull_request` mode (Max, 9 Nov 2026):

```bash
gh pr merge <nr> --squash --admin --delete-branch
```

The bypass covers merging PRs only; direct pushes to `main` stay blocked, for Max too. Leave the
ruleset's bypass list as it is. Open the PR, put it on staging (below) and post the staging link in the PR.
When several open PRs touch the same files, merge them one by one and bring the next one up to date
with `main` before approving it: a push after an approval dismisses it.

## Review means staging (Max, 6 November 2026)

A review is never a GitHub diff or markdown. The reviewer sees the full rendered page, exactly as
it would go live, and gets told what to look for. Every PR that changes what a visitor sees gets:

1. **A staging deploy:** `scripts/staging.sh pr-<n> <n>` (several PRs together:
   `scripts/staging.sh <name> <n> <n> ...`). It builds origin/main plus those PRs with
   `STAGING=1`, so pages with `status: review` render too, and deploys to the separate Pages
   project `implementeren-ai-staging`: `https://<name>.implementeren-ai-staging.pages.dev`.
   Password protected (`STAGING_WACHTWOORD`, a variable on that project only; never put the
   password in the repo, a PR or a page), always noindex, orange "Staging, niet live" bar.
   Production is untouched: it only deploys via `.github/workflows/deploy.yml`.
2. **A review sheet:** what to look for, per page, concretely. The specific facts and prices to
   check, each with the source link; claims that need a human eye; what was deliberately left
   out; links and CTA; how it looks on a phone. Not a generic checklist. The sheet is a temporary
   page at `claudezakelijk.pages.dev/tijdelijk/<slug>/` (see the claude-cowork-practice repo) and
   links straight to the staging URLs.
3. **Show it:** open the review sheet for Max (`~/.claude/helpers/chrome-open.sh --prive`) and
   put the staging link and the sheet link in the PR.

Content waiting for a launch carries `status: review`: it is not built in production, only on
staging. Staging needs `gh` and the Pages-only API token in
`~/.config/cloudflare/implementeren-staging-token` on the M1 Pro (no expiry; `scripts/staging.sh`
reads it itself). Never print it. Without it, wrangler falls back to `npx wrangler login`, whose
OAuth expires.

## Adding a page

1. Create the page under `src/pages/` wrapping `BasisLayout`
   (`import BasisLayout from '../layouts/BasisLayout.astro'`, pass `titel`, `beschrijving`, `pad`).
2. Add its route to `src/data/public-pages.json`. `scripts/check-pages.mjs` fails the build for any
   route that is not listed there.
3. If it should be indexed by Google, it must also fall under the `zakelijk` allowlist in
   `src/data/indexering.mjs`. Everything outside that list gets noindex automatically.
4. `npm run build` must pass clean (`check-pages`, `astro build`, `check-dist`).

`functions/_indexering.json` and `functions/_redirects.json` are generated by
`scripts/gen-edge.mjs`; never hand-edit them. Redirects go in `public/_redirects`.

## Content rules the build enforces

`scripts/check-dist.mjs` fails the build on: e-mail addresses other than @implementeren.ai
(and the old @claudezakelijk.nl during the transition), the
names of people other than Camiel, the names Proxuma or Dxfferent, placeholders or HTML comments
on indexable pages, and a page H1 inside `.reveal-target`. `scripts/quality-gate.py --all` checks
published content and runs in the deploy workflow before the build.

## House styling tokens (Tailwind v4, from `src/styles/global.css`)

Surfaces `bg-papier` / `bg-white` · text `text-inkt` / `text-inkt-zacht` · accent terracotta
`text-accent-diep` (use `-diep` for AA contrast) · teal for the one primary CTA only `bg-teal` ·
borders `border-lijn` · fonts `font-serif` (headings) / `font-sans` (body) · containers
`mx-auto max-w-3xl px-5 py-16 md:py-24` · cards `card-shadow rounded-xl border border-lijn
bg-white p-5` · section header rule: class `sectie-lijn` on an `<h2>` · long prose:
`class="prose prose-stone max-w-none"`. Do not invent new colors. Content language follows the
topic (Dutch or English). No em dashes, no AI-slop phrasing.
